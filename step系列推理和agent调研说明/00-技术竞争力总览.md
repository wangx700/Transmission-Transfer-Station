# Step 系列推理与 Agent 技术竞争力报告：总览

**整理日期：2026-10-12，北京时间。**本版将模型代际、底层结构、Agent框架与昇腾部署分别成文。prefill/Indexer/KV仅作原理说明；已有PPT/图片另附统一说明及副本。旧版报告和图集保留。

## 1. 核心判断

**Step 5 Preview的重点是大容量稀疏模型、长程任务与Step-Code的组合。**官方600B/27B、1M上下文是能力规模背景；Sparse GQA/块合并和长程RL系统细节主要来自标注为非官方的团队技术转述。AA本轮仍为44分，呈现有竞争力的能力与任务费用组合，但不支持“所有模型全球第三”或“全面领先”的结论。[官方发布](https://www.stepfun.com/step-5-preview)、[AA](https://artificialanalysis.ai/models/step-5)

**Step 3.5/3.7的价值是可核查、可适配的实现基础。**混合注意力、逐head输出gate、稀疏MoE路由及MTP有配置/代码；3.5后训练报告提供失配处理与EP均衡设计，3.7增加视觉。A3/950已有Ascend合入与验证证据，但具体Runner、量化、多模态和长上下文必须逐项核验。[官方配置](https://huggingface.co/stepfun-ai/Step-3.7-Flash/blob/main/config.json)、[Ascend支持PR](https://github.com/vllm-project/vllm-ascend/pull/10556)

**Step-Code的可借鉴价值在运行机制。**CLM保留原始历史并管理工作上下文，子会话控制返回内容，Goal管理继续/停止/恢复，插件与工具提供交付能力。迁移到MindSpeed-Agent时应补充数据与资源契约，不能把新增Skill当作运行时能力的替代。[Step-Code](https://github.com/stepfun-ai/Step-Code)、[MindSpeed-Agent](https://gitcode.com/Ascend/MindSpeed-Agent)

## 3. 对标与工程取舍

Step5与GLM-5.3、Kimi K3有同页公开任务对照；软件实现/仓库理解呈现优势信号，SWE-Marathon与AutomationBench则不能宣称领先。DeepSeek V4.1的金融对照仅支持具体任务比较，V4及Hy4 Preview缺少足够同条件证据，不制造总体排名。Step3.5/3.7不同版本benchmark也不直接拼表排名。

推理团队应优先研究“历史选择与数据布局”“MoE路由语义与rank拖尾”“MTP净收益”“训练/rollout概率一致性”；Agent团队优先研究“上下文保真”“子任务结果契约”“验收和取消恢复”。这些机制多数不是独有发明，竞争力来自组合质量和同条件结果。

Step5目前未获得vLLM-Ascend公开主线开箱支持的直接证据；3.5/3.7更适合先做NPU基线。建议先完成短文本BF16，再扩展工具、多模态、MTP、量化和长上下文。版本/架构未知明确记录unknown，不用旧代字段补齐Step5。

## 4. 数字与证据的使用规则

1. 1/8只指报道中的Indexer/Top-k局部成本；长程RL超过3倍为系统组合自述，均非API端到端倍数。
2. 27B激活不等于只存27B权重；1M上下文不等于输入1M后还可额外生成64K。
3. API吞吐不等于同硬件kernel性能；厂商最佳案例不等于平均成功率。
4. Step-Code成绩不能归为模型裸能力或直接外推到NPU；PaCoRe/StepMesh/StepTronOSS不自动成为Step5已证实内部栈。
5. 官方测试、媒体转述、博客疑点、通用工程解释分别标注。动态图表保留观测时点，正式部署前重新确认版本和开放状态。
