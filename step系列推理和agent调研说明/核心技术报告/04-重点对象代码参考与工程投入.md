## 2. Step 3.5 / 3.7：从源码语义到推理收益

### 代码与接口流

- **模型原始语义：** [3.5模型仓](https://huggingface.co/stepfun-ai/Step-3.5-Flash)、[3.7配置](https://huggingface.co/stepfun-ai/Step-3.7-Flash/blob/main/config.json)、[3.7实现](https://huggingface.co/stepfun-ai/Step-3.7-Flash/blob/main/modeling_step3p7.py)。流程为 `hidden → 混合attention及输出gate → MoE router/top-k → 专家计算/加权合并 → 下一层`；3.7另有 `图像processor → vision encoder/projector → 语言主干`。Gate调节attention输出，不改变窗口，也不自动跳过计算。
- **昇腾后端：** [支持PR #10556](https://github.com/vllm-project/vllm-ascend/pull/10556)、[Step patch](https://github.com/vllm-project/vllm-ascend/blob/c076a131097fdfac9db4b57c8cf55bfd45ea0ca5/vllm_ascend/patch/worker/patch_step3p5.py)、[MTP proposer](https://github.com/vllm-project/vllm-ascend/blob/c076a131097fdfac9db4b57c8cf55bfd45ea0ca5/vllm_ascend/spec_decode/step3p5.py)。服务路径为 `模型加载/后端patch → runner调度 → attention/MoE → 输出`；MTP增加 `草稿提出 → target验证 → 接受/回退 → 缓存更新`。proposer类为`AscendStep3p5MTPProposer`。
- **3.7多模态入口：** [vLLM step3p7.py](https://github.com/vllm-project/vllm/blob/ced6857afa0ea7b2e3f0846a62e1394e90f15607/vllm/model_executor/models/step3p7.py)；[MRV2跟踪任务](https://github.com/vllm-project/vllm-ascend/issues/14205)。具体状态应按部署时版本重查，不由文本测试推导视觉支持。

### 已完成支持与后续投入的界线

**基础推理适配已完成，应直接复用。** PR #10556于2026-07-13合入，记录Ascend950和A3测试，包含功能与MTP运行记录；还增加Step3.5的flashcomm1及3.5/3.7的split_qk_norm_rope支持。报告不将这些既有工作列为待开发项。[合入与测试记录](https://github.com/vllm-project/vllm-ascend/pull/10556)

**只有新增路径才可能需要适配开发。** 2026-10-12复核Issue #14205仍为open，其正文明确Step3.7在MRV1可用，任务为迁移到MRV2。MRV2未完成记录不影响已有MRV1支持结论；不需要MRV2的部署无需把该任务计入投入。[MRV2任务及范围](https://github.com/vllm-project/vllm-ascend/issues/14205)

**部署方的首项工作是环境与业务验收。** 核对路由bias只用于选择还是也进入混合权重、共享专家、gate、缩放及MTP接受策略；检查参考输出/logprob。已有模型支持代码值得复用，但不能以“接口返回200”替代验收。

**第二步才是时延优化。** MoE每token选少数专家不等于跨卡负载均匀。采集每专家/每rank token数、专家GEMM有效批量、dispatch/combine通信时间和最慢rank耗时，再判断是否需专家重排或副本、容量/并行配置调整。EPLB必须与后端能力和权重更新一致，不能直接在推理时改变训练好的路由决策来追求均匀。只有排队、通信和慢rank确实下降且质量/SLO守住，才能报告时延收益。

**RL另需采样一致性验证。** [SteptronOSS flow controller](https://github.com/stepfun-ai/SteptronOss/blob/dev/steptronoss/core/generators/flow_controller.py)可参考`FullyAsyncFlowController`的生成、获取训练样本与权重同步控制。接口概念链为 `生成请求 → 样本/策略版本 → 训练消费 → 权重同步 → 后续生成`。版本标记不自动保证所有token使用同一策略；需要核对实际生成器和logprob路径。移植调度代码不能替代RL算法与奖励设计。

人员投入首先是部署与性能/质量验收责任人。仅当新增MRV2路径、硬件/量化组合或实际算子/EP瓶颈需要改造时，再引入后端、内核或分布式工程师；RL采样接入另需训练工程师。这些是增量工作，不是从零完成3.5/3.7推理适配。

## 3. Step 5 Preview：先评测能力，再评估模型级适配

**关注稀疏访问与长任务的组合。** [官方Step5页面](https://www.stepfun.com/step-5-preview)用于能力和厂商测试设置；[官方模型文档](https://platform.stepfun.ai/docs/en/guides/models/step-5-preview)用于服务规格；[技术报道](https://news.qq.com/rain/a/20260920A06EUP00)中的Sparse GQA/Indexer、Top-k合并属于报道证据，不能替代完整源码。

原理链为 `Q/K/V投影 → Indexer候选评分/Top-k → 稀疏K/V访问 → attention → MoE`。**生成K/V与选择读哪些K/V是两个步骤。** Prefill也需要执行attention，稀疏模型可在该阶段执行Indexer；批量query之间存在复用机会，但因果遮罩和各query权重仍需独立处理。共同历史块的收益是尽量复用已加载的K/V、减少小块访问与调度，不是多个query共用一个attention结果。Decode中的复用可能来自批量query、推测验证或特定分块实现，不能把单请求逐tokendecode默认描述成多query联合计算。

报道中的Indexer/Top-k成本降至1/8是局部指标。端到端仍包含投影、KV访问、attention、MoE、通信和排队；公开信息未给出完整消融与硬件条件，不能写成模型整体加速8倍。

**两条工作线应区分。** API线可直接开展固定预算的代码/工具/长程任务评测，记录成功率、回合数、修复次数、上下文增长与每成功任务成本。NPU线需要先取得完整checkpoint/config/processor、源码与许可，再核对vLLM registry、稀疏索引布局、Paged KV、分块合并、MoE/EP、图模式和量化支持。[vLLM-Ascend仓库](https://github.com/vllm-project/vllm-ascend)、[vLLM registry](https://github.com/vllm-project/vllm/blob/ced6857afa0ea7b2e3f0846a62e1394e90f15607/vllm/model_executor/models/registry.py)是后端检查入口，不是Step5已支持的证明。

工程投入需要模型接入、NPU算子/缓存、分布式并行及评测角色协作。依赖未齐全时，不宜给人天承诺；先交付算子清单、容量估计、接口差异和最小验证方案。Step-3的[StepMesh](https://github.com/stepfun-ai/StepMesh)可研究通信/Attention–FFN分离，但它与Step5 Indexer不是同一优化，不可直接视为Step5实现。

## 6. 投入决策与验收产物

表注：P0/P1/P2含义同首表；投入范围为建议，不对应固定人数或工期。实际立项需先确认硬件、代码/权重开放范围、业务SLO与质量基线。

| 阶段 | 人力应解决的问题 | 最小交付与进入下一步条件 |
|---|---|---|
| P0：已有路径复用 | 复用3.5/3.7已完成推理支持，完成目标环境与业务验收；StepCode式证据handoff/资源控制 | 固定版本环境卡、正确性样例、延迟/吞吐基线；任务可取消、结果可追溯 |
| P1：功能组合与场景验证 | MTP/EP/长上下文；RL采样；Step5 API长程任务；音频API交互 | 同条件质量/成本/时延对比；每项收益有消融；异常恢复和业务成功证据 |
| P2：专项后端研发 | Step5稀疏attention/KV；Audio3完整音频链；必要时AFD/通信适配 | 前置资料齐全后给算子/接口清单；完成参考对齐、NPU单模块与完整链验收 |

**可以直接复用的是已有组件与设计，不是收益数字。** 优先投入3.5/3.7基线和Agent运行契约；Step5与Audio3先明确资料和硬件依赖，再决定内核研发范围。一个项目已有主干支持、一个局部算子更快、一个框架评分更高，均不足以证明完整业务链可用或更省成本。
