## 2. Step5：能力、评测与技术证据

**业务能力。** 官方定位覆盖软件工程、长文档研究、多步Agent及多模态分析，强调专业知识工作与金融；这是产品定位，不能等同于各业务准确率已验收。当前文档列文本/图像/视频输入、文本输出，支持工具调用与结构化输出；上下文/最大输入标记1M，最大输出64K。工具和执行环境由应用提供，输入与输出仍受总上下文预算约束。[官方模型文档](https://platform.stepfun.ai/docs/en/guides/models/step-5-preview)

**独立评测。** 本次AA页列Intelligence Index **44**、每项指数任务加权成本约**1.03美元**、输出速度**88.5 tokens/s**、TTFT **2.87秒**；摘要位置为**40/227**。这些是2026-10-12页面快照及其API测试口径，不是业务准确率、全球固定排名或NPU性能；输出速度也不能代替完成长任务的耗时。AA称其能力–价格组合有竞争力，同时提示输出较长。[AA模型页与指标定义](https://artificialanalysis.ai/models/step-5)

**厂商榜单历史记录。** 前轮发布页记录ProgramBench：Step5 80.5、GLM-5.3 72.0、Kimi K3 77.8；SWE-Marathon Partial Score：72.7、67.4、84.4。Step用High，对照用Max，预算未统一。此次发布页正文未被检索工具提取，因此这些数值保留为前轮记录，不称为此次重新确认；它们不支持“长程全面领先”或对DeepSeek V4/V4.1、Hy4 Preview建立统一排名。[厂商发布页](https://www.stepfun.com/step-5-preview)

**架构证据。** 原资料列600B总参数/27B激活；92层、Sparse GQA及相邻query选择合并等细节仍按媒体转述处理。Indexer/Top-k局部成本降至1/8不能写成整模型推理加速8倍；完整层配置、缓存布局、生产RL/EP实现需公开配置与源码核对。

## 3. 推理与Agent值得借鉴的核心机制

**稀疏访问与K/V复用：** K/V投影负责生成历史状态，Indexer负责选取attention读取的候选。Prefill也有attention，稀疏实现可执行Indexer；相邻query候选重叠时可在融合调度中复用已加载的K/V，但各query的因果遮罩、权重和输出仍独立。共同历史块不是共同attention结果，普通逐token Decode也不默认具有同请求多query复用条件。Step5具体实现粒度未核实。

**MoE、EP与EPLB：** MoE选少数FFN专家，EP分布专家权重/计算，EPLB重排专家及热点副本以减少慢rank拖尾。模型稀疏不自动保证负载均衡。vLLM-Ascend已有EPLB实现，应复用并验证目标模型、runner、权重格式与设备组合，不能把通用支持当成Step全组合认证。[Ascend EPLB指南](https://docs.vllm.ai/projects/ascend/en/latest/user_guide/feature_guide/expert_parallelism_load_balancer.html)

**AFD与StepMesh：** Step-3将Attention与FFN资源池分离，目标是分别配置KV与计算资源、增大FFN有效batch；StepMesh优化跨池交接。已有afd-plugin包含Ascend worker/runner和CAM Connector，应先复用，不默认重写通信后端；它不证明Step模型AFD切分或StepMesh NPU后端已经完成。[Step-3论文](https://arxiv.org/html/2507.19427)、[AFD运行设计](https://github.com/vllm-project/afd-plugin/blob/bf5bd280b7481358fc0df4a8ec5897b12be73802/docs/design/module/attention_runtime.md)

**后训练与采样：** 3.5的MIS-PO处理训练/rollout策略失配；MTP收益需要同时看接受率、验证开销和样本质量。异步生成的版本标签、背压和权重同步不替代logprob对齐；优化目标是有效训练样本与任务质量，不只是原始tokens/s。[3.5论文](https://arxiv.org/html/2602.10604v2)、[SteptronOSS流控](https://github.com/stepfun-ai/SteptronOss/blob/dev/steptronoss/core/generators/flow_controller.py)

**长任务与语音Agent：** StepCode管理工作上下文、子任务结果与Goal状态；模型负责规划和工具决策。Audio3 Realtime的TWS将推理与分段表达并发推进，异步工具还需需求版本、取消及结果一致性。Gen/Music中间计划提供创作Agent介入点，但计划合法、产物遵循和音质合格须分别验收。[Step-Code](https://github.com/stepfun-ai/Step-Code)、[Realtime论文](https://arxiv.org/html/2609.14005)、[Gen论文](https://arxiv.org/html/2609.12945)、[Music论文](https://arxiv.org/html/2609.16034)

## 4. 人力投入与推进次序

表注：工程建议，非人天承诺。已有支持直接复用；仅在业务需要、验证失败或瓶颈明确时追加研发。完整模型资料是Step5/Audio3本地适配的前置条件。

| 工作类型 | 近期工作 | 何时需要专项人力 |
|---|---|---|
| 已完成支持复用 | 3.5/3.7部署、固定软硬件与模型版本 | 不重复立基础适配研发项 |
| 业务验证与调优 | 质量、TTFT/TPOT、尾延迟、EP/MTP收益、RL采样；Step5 API任务成本 | 性能/质量与训练工程师按业务介入 |
| Agent集成 | StepCode式结果契约、NPU租约、取消恢复；音频工具闭环 | 运行时/应用工程师与平台工程师协作 |
| 增量后端研发 | MRV2、缺失功能组合、经测量确认的算子/通信瓶颈 | 推理后端、算子/分布式工程师；先明确改动与验收目标 |
| 资料依赖型研究 | Step5稀疏attention/KV、Audio3完整本地链、Step模型AFD | 资料齐全后列模块差异并立项，不以论文替代可部署实现 |
