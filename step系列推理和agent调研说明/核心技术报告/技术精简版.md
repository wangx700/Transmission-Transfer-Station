# Step系列推理与Agent技术精简版

资料时点：2026-10-12（北京时间）。基于现有调研压缩，未新增实测。仅保留结构、执行流程、优化原理和代码证据；Step5未公开的细节标为报道，Audio3按论文机制介绍。

## 1. Step 3.5 / 3.7：保留结构与推理协同设计

表注：B为十亿参数；语言主干与视觉/MTP附加参数分别记。配置来自既有官方论文/模型仓核验，不能用3.5/3.7配置填补Step5未公开字段。

| 模型 | 结构参数 | 主要计算路径 |
|---|---|---|
| Step 3.5 | 196B总参数/11B激活的语言主干；45层，hidden 4096；含MTP另有198B/13B口径 | 33 SWA+12 Full；3 dense+42 MoE |
| Step 3.7 | 196B语言主干+约1.8B视觉；语言主干延续3.5 | SWA窗口512；288 routed experts选8+1 shared；3层MTP；新增视觉encoder/projector |
| Step5 Preview | 原发布资料600B/27B；92层属媒体转述 | MoE；Sparse GQA/Indexer与块合并属报道，精确heads、专家数与KV布局未核实 |

依据：[3.5论文](https://arxiv.org/html/2602.10604v2)、[3.7配置](https://huggingface.co/stepfun-ai/Step-3.7-Flash/blob/main/config.json)、[Step5发布](https://www.stepfun.com/step-5-preview)、[Step5架构报道](https://news.qq.com/rain/a/20260920A06EUP00)。

**混合注意力与MTP协同：降低长上下文开销，保留并行验证能力。** Step 3.5以3个窗口512的SWA层配1个Full层，并增加SWA query heads、采用head-wise gate，补偿简单窗口化带来的质量损失。Gate允许窗口缺少有用信息时抑制该head输出。选择SWA还考虑了它能用KV masking进行投机解码并行验证；这是比“窗口限制访问”更值得借鉴的设计取舍。[论文架构与消融](https://arxiv.org/html/2602.10604v2#S2)、[门控实现](https://huggingface.co/stepfun-ai/Step-3.7-Flash/blob/main/modeling_step3p7.py)

**轻量MTP：降低提出多token候选的额外成本。** 三个预测模块采用SWA+Dense FFN；主训练主要训练第一个，后期复制并联合训练其余模块。通过候选生成与主模型验证减少串行解码轮次；净收益仍取决于接受长度和验证成本。[论文MTP设计](https://arxiv.org/html/2602.10604v2#S2)、[Ascend proposer](https://github.com/vllm-project/vllm-ascend/blob/c076a131097fdfac9db4b57c8cf55bfd45ea0ca5/vllm_ascend/spec_decode/step3p5.py)

稀疏MoE容量/激活参数见上表。Step的EP-group训练约束用于补足“全局专家均衡不保证micro-batch内rank均衡”的问题；通用router步骤、服务期EPLB和RL概率对齐属于专题实现细节，不单列为Step推理优势。详见[MoE/EP专题](https://github.com/wangx700/Transmission-Transfer-Station/blob/main/step%E7%B3%BB%E5%88%97%E6%8E%A8%E7%90%86%E5%92%8Cagent%E8%B0%83%E7%A0%94%E8%AF%B4%E6%98%8E/%E6%A0%B8%E5%BF%83%E6%8A%80%E6%9C%AF%E6%8A%A5%E5%91%8A/05-MoE%E4%B8%8EEP%E6%9C%BA%E5%88%B6%E3%80%81%E6%8B%96%E5%B0%BE%E6%B2%BB%E7%90%86%E5%8F%8A%E6%98%87%E8%85%BE%E5%B7%A5%E7%A8%8B%E5%88%A4%E6%96%AD.md)、[推理与后训练专题](https://github.com/wangx700/Transmission-Transfer-Station/blob/main/step%E7%B3%BB%E5%88%97%E6%8E%A8%E7%90%86%E5%92%8Cagent%E8%B0%83%E7%A0%94%E8%AF%B4%E6%98%8E/%E6%A0%B8%E5%BF%83%E6%8A%80%E6%9C%AF%E6%8A%A5%E5%91%8A/01-%E6%8E%A8%E7%90%86%E6%8A%80%E6%9C%AF%E6%A0%B8%E5%BF%83%E5%88%86%E6%9E%90.md)。

## 2. Step5 Preview：稀疏访问与长程执行

**计算链：** `Q/K/V投影 → Indexer评分与Top-k → 选中历史K/V → 稀疏attention → MoE`。GQA让多个query heads共享K/V heads，减少KV表示量；稀疏选择进一步减少读取位置。两项作用于不同维度，不能仅凭名称推定具体缓存布局。

**Prefill与复用。** K/V投影只负责生成状态；attention还需要读取历史并计算权重，稀疏实现可在Prefill执行Indexer。相邻query的Top-k重叠时，可以融合调度并复用已加载K/V，减少重复搬运及碎片；每个query仍有独立的因果遮罩、softmax和输出。示意“历史块”可以包含多个token位置，但Step5具体选择粒度未确认。普通单请求Decode每轮通常只有一个新query；同请求多query复用需批量验证等额外条件。

报道的Indexer/Top-k成本降至1/8属于局部优化；不能据此计算完整推理速度。投影、attention、MoE、通信与排队仍在执行链中。[机制报道](https://news.qq.com/rain/a/20260920A06EUP00)

**长程能力应拆为模型与框架。** 模型负责跨材料推理、规划、工具选择及反馈修正；框架负责历史管理、执行、恢复与完成验收。Step5官方API提供1M上下文、64K最大输出、工具调用和结构化输出，适合承载长程循环；完整生产RL方案尚不能由公开材料逐项复现。[官方接口能力](https://platform.stepfun.ai/docs/en/guides/models/step-5-preview)

## 3. StepAudio：实时调度与生成计算分工

表注：下面是Audio3论文机制；Hz指音频表示帧率，不是波形采样率或实际运行速度。已有Audio2/R1/Skills代码仅作接口参考。

| 分支 | 技术流程 | 核心优化对象 |
|---|---|---|
| Realtime | 音频/交互状态→推理与分段表达并发；工具异步执行→证据回流 | TWS缩短首段响应关键路径；全双工处理听说交叠与打断；工具执行不阻塞整个会话 |
| Gen | 12.5Hz、16码本；主LLM预测首码本→小Transformer补其余15个→因果codec | 将跨时间组织与帧内声学细节分工，减少大模型串行预测位置 |
| Music | ABC计划→50Hz单码本AR→Flow-Matching DiT→VAE波形 | 可编辑计划与声学渲染分离，分别优化规划、序列生成和音频合成 |

Realtime中停止播放不等于取消工具；需求变化后要处理旧任务/旧结果。Gen/Music则需分别维护码本/codec与渲染latent状态，不能共用一套生成成本估算。[Realtime](https://arxiv.org/html/2609.14005)、[Gen](https://arxiv.org/html/2609.12945)、[Music](https://arxiv.org/html/2609.16034)

代码入口：[Realtime Console](https://github.com/stepfun-ai/Step-Realtime-Console)用于采集、WebSocket事件和播放；[Audio2 stepaudio2.py](https://github.com/stepfun-ai/Step-Audio2/blob/main/stepaudio2.py)用于预处理/模板/生成；[StepAudio-Skills](https://github.com/stepfun-ai/StepAudio-Skills)封装TTS、流式ASR和R1.1语音推理API。它们不证明Audio3完整模型链已在昇腾部署。

## 4. StepCode：上下文与任务状态机制

执行链为 `Goal/预算 → 模型规划 → 工具或子任务 → 结果/证据 → 上下文更新 → 验收/续跑`。值得借鉴的是宿主运行机制：

- **CLM与压缩：** 维护原始历史和工作视图，编辑旧观察以控制日志膨胀；压缩执行`shouldCompact → prepareCompaction → CompactionEntry → 重建`，保留目标、约束与失败证据。[CLM](https://github.com/stepfun-ai/Step-Code/blob/main/packages/coding-agent/docs/context-management.md)、[压缩实现](https://github.com/stepfun-ai/Step-Code/blob/main/packages/coding-agent/src/core/compaction/compaction.ts)
- **子会话：** 独立执行、限制并发，主会话接收状态与关键结果，完整内容保留在details；减少主上下文重复信息。[executeSubagent](https://github.com/stepfun-ai/Step-Code/blob/main/packages/coding-agent/src/features/subagent/execute.ts)
- **Goal：** 持久化目标、预算、取消与续跑状态；完成必须由测试或产物验收。[生命周期](https://github.com/stepfun-ai/Step-Code/blob/main/docs/goal-lifecycle.md)
- **Skill/Plugin：** 加载方法说明与工具组件；并发、取消、恢复需宿主实现。MindSpeed-Agent应优先补结果契约及NPU设备/端口/进程租约。[skills.ts](https://github.com/stepfun-ai/Step-Code/blob/main/packages/coding-agent/src/core/skills.ts)、[MindSpeed-Agent](https://gitcode.com/Ascend/MindSpeed-Agent)

## 5. 昇腾落点

**3.5/3.7基础推理已完成支持，直接复用。** PR #10556已合入，记录A3/950功能与MTP；MRV1可用，3.7 MRV2是单独新增路径。投入集中于实际业务调优与所需功能组合。[支持PR](https://github.com/vllm-project/vllm-ascend/pull/10556)、[MRV2任务](https://github.com/vllm-project/vllm-ascend/issues/14205)

**Step5与Audio3完整本地链尚未确认。** Step5重点核对稀疏索引、Paged KV、MoE/EP和权重映射；Audio3增加encoder、RVQ/codec或DiT/VAE与流式状态。API工具集成与这些模型后端工作分开。

**AFD可作为系统优化参考。** Step-3将Attention/KV与FFN计算分池，汇聚FFN有效batch；StepMesh执行`PushPull → GetBatch → FFN计算 → Respond → Wait`。昇腾已有afd-plugin NPU运行与CAM Connector，应优先复用；Step模型切分与通信收益仍需验证。[StepMesh](https://github.com/stepfun-ai/StepMesh)、[AFD设计](https://github.com/vllm-project/afd-plugin/blob/bf5bd280b7481358fc0df4a8ec5897b12be73802/docs/design/module/attention_runtime.md)
