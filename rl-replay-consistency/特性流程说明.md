# 六项特性的接口、格式与处理流程

源码统一固定到 2026-10-23 核对的主线 `432b1003f8ea7c871750f27bc82815a7ad0252d5`。步骤编号用于和[上一周 PR 表](上一周PR与流程映射.md)对应。这里提供的是源码分析，未执行硬件正确性/性能验证。

## M：Sampling Mask

启用：`LLM(..., return_sampling_mask=True, logprobs_mode="processed_logprobs")`；请求 `temperature>0`、`top_k>0`。不是每请求独立的导出开关。

```text
M1 请求与引擎校验
 → M2 logits processor：bias / penalty / temperature / min-p
 → M3 top-k/top-p 过滤，被排除的 logits 设为 -inf
 → M4 采样后捕获 processed_logits 的有限支持集
 → M5 异步 D2H、CSR、请求切片、外部 ragged list
 → trainer 使用同一支持集 S 计算 log_softmax
```

代码：[Sampler](https://github.com/vllm-project/vllm/blob/432b1003f8ea7c871750f27bc82815a7ad0252d5/vllm/v1/worker/gpu/sample/sampler.py)、[mask tensor/bitmask](https://github.com/vllm-project/vllm/blob/432b1003f8ea7c871750f27bc82815a7ad0252d5/vllm/v1/worker/gpu/sample/output.py)、[CSR](https://github.com/vllm-project/vllm/blob/432b1003f8ea7c871750f27bc82815a7ad0252d5/vllm/v1/outputs.py)、[配置校验](https://github.com/vllm-project/vllm/blob/432b1003f8ea7c871750f27bc82815a7ad0252d5/vllm/config/vllm.py)。

内部 `token_ids:int32[B×Q,W]`、`counts:int32[B×Q]`、`packed_mask:uint8[B×Q,ceil(V/8)]`；W 上限 2048。counts>W 时从 little-bit-order bitmask 恢复全量支持集，不截断为 W。CPU CSR 为 flat int32 与 offsets int64；外部 `list[list[int]]` 的第 i 行对齐第 i 个输出 token。Q 为预留输出槽数；普通 speculative 只导出 committed target supports。

trainer：`logπθ(a|s,S)=zθ[a]−logsumexp(zθ[j],j∈S)`。温度、惩罚与权重版本仍须对齐。引擎级打开会关闭融合 sampler，存在算子、内存及传输成本；adaptive verification/diffusion/custom logits processors 等组合由校验拒绝。#61996 位于 M3，优化过滤路径，不改变 M5 的公共格式。

## I：Index Replay

```text
I1 当前主线：模型 indexer → score/top-k → topk_indices_buffer
 → I2 稀疏 attention 消费位置，生成 hidden states

待合入闭环：在真实生产/消费点 capture
 → 共享 buffer 覆盖前 snapshot → async D2H
 → 按请求/token/层映射保存、prefix 恢复、accepted-token 裁剪
 → API 返回 → trainer sparse attention 固定选择
```

代码：[sparse_attn_indexer](https://github.com/vllm-project/vllm/blob/432b1003f8ea7c871750f27bc82815a7ad0252d5/vllm/model_executor/layers/sparse_attn_indexer.py)。现有 I1/I2 不等于完整返回链路。

当前 [#49555](https://github.com/vllm-project/vllm/pull/49555) 的标题已变为 ordinary raw indexer selections replay，仍 Open/Draft，不能继续把旧 PR 描述的广泛模型/编码声明当作当前已支持。公共格式需明确 token 坐标、压缩/KPool 坐标、实际有效长度、层间复用及无效值；本报告不替未合入 PR 编造稳定 schema。[RFC #47280](https://github.com/vllm-project/vllm/issues/47280) 是需求入口。

## R：R3 路由记录

```text
R1 enable_return_routed_experts → AuxOutput 配置与能力检查
 → R2 创建 Capturer、绑定 router 或融合 kernel routing sink
 → R3 router topk_ids →恢复本 DP rank 的完整 token 行 →持久 GPU buffer
 → R4 prepare_output/snapshot →异步 CPU transfer
 → R5 process_output：去 rejected 行、block/tail 按 KV hash 保存、命中恢复
 → R6 请求结束 materialize → CompletionOutput/HTTP → trainer 重放专家选择
```

代码：[capture、TP 行恢复与 snapshot](https://github.com/vllm-project/vllm/blob/432b1003f8ea7c871750f27bc82815a7ad0252d5/vllm/model_executor/layers/fused_moe/routed_experts_capturer.py)、[worker](https://github.com/vllm-project/vllm/blob/432b1003f8ea7c871750f27bc82815a7ad0252d5/vllm/distributed/aux_output_connector/worker.py)、[block 保存与 materialize](https://github.com/vllm-project/vllm/blob/432b1003f8ea7c871750f27bc82815a7ad0252d5/vllm/distributed/aux_output_connector/routed_experts.py)。

GPU 捕获 int32 `[max_batched_tokens,L,K]`；snapshot 转 uint8（E≤256）或 uint16；导出 `[P+G−1−O,L,K]`。L 来自 `get_total_num_hidden_layers()`；只对 capture 绑定层解释，初始零槽不是有效“专家0”。记录逻辑专家 ID，trainer 需映射到自身 EP 专家布局。

HTTP 字符串是 `.npy` 文件再 base64，不是裸 bytes：

```python
experts = np.load(io.BytesIO(base64.b64decode(choice["routed_experts"])),
                  allow_pickle=False)
```

输入位置 `t=O+r` 的路由行 r 预测下一个 token；输出 y[j] 的预测位置为 `t=P+j−1`。最后 sampled token 尚未作为下一轮输入，缺其自身路由行。不能直接把后 G 行当作生成 token 自身路由。

MRV2/generate/MoE/prefix cache 是当前树内要求；PP>1、DCP/PCP>1、adaptive verification 及配置列举的若干 PD connectors 受限。host LRU 容量不足会影响路由块恢复。#61388 改 R3 的 TP/SP 行还原，不是放开所有并行限制；#62302 是 R1–R6 文档化。

## H：Hidden States

三种能力应分开：生成内部的最终 hidden tensor；EAGLE3/DFlash 用的 aux hidden tensors；普通 rollout 请求将激活导出到 trainer。前两者存在，不推出第三者通用支持。

```text
H1 支持的 speculative 模型配置 aux 层
 → H2 model.forward 在选定层边界调用 _maybe_add_hidden_state
 → H3 返回 final hidden tensor 与 aux_hidden_states 列表
 → H4 runner/proposer 提取、组合并供辅助模型使用

拟议外部回传：请求选择 response window → capture 指定行
 →异步 pinned CPU 拷贝与完成同步 →序列化 →trainer
```

代码：[EagleModelMixin / SupportsEagle3](https://github.com/vllm-project/vllm/blob/432b1003f8ea7c871750f27bc82815a7ad0252d5/vllm/model_executor/models/interfaces.py)、[GraniteMoe](https://github.com/vllm-project/vllm/blob/432b1003f8ea7c871750f27bc82815a7ad0252d5/vllm/model_executor/models/granitemoe.py)、[GraniteMoeShared](https://github.com/vllm-project/vllm/blob/432b1003f8ea7c871750f27bc82815a7ad0252d5/vllm/model_executor/models/granitemoeshared.py)、[MRV2 hidden-state extraction](https://github.com/vllm-project/vllm/blob/432b1003f8ea7c871750f27bc82815a7ad0252d5/vllm/v1/worker/gpu/spec_decode/extract_hidden_states.py)。

内部 tensor 行轴是本次执行的 token 行，通常形如 `[N,H]`；aux 是若干 tensor 的列表，不能统一宣称是 `[response_len,num_layers,H]`。层边界、pre/post norm、padding/accepted 行、PP 和 residual 语义取决于模型实现。#61110 改 H2/H3：Granite 增加 aux 收集和支持接口，不新增通用 JSON 字段。

[#57736](https://github.com/vllm-project/vllm/pull/57736) 窗口捕获回传仍 Open，PR 描述中的性能/测试仅限作者分支；[#37002](https://github.com/vllm-project/vllm/pull/37002) 仍 Open，Phase 1 的插件抽象也不等于完成 runner hook。模型多模态组件调用 `output_hidden_states=True` 不构成普通生成 API 的公共导出证据。

## L：Logprob 与固定轨迹诊断

```text
L1 请求选择 logprobs / prompt_logprobs / 指定 token ID 与 raw/processed 模式
 → L2 forward hidden states → lm_head logits
 → L3 原始或处理后 logits 计算分数与 ranks
 → L4 runner 异步输出 →按实际 token 位置组装
 → L5 generate / OpenAI endpoint / derender 按各自协议裁切、解码、流式返回
 → trainer 对齐 token、权重版本、归一化空间，计算 ratio/KL
```

代码：[SamplingParams](https://github.com/vllm-project/vllm/blob/432b1003f8ea7c871750f27bc82815a7ad0252d5/vllm/sampling_params.py)、[MRV2 logprob](https://github.com/vllm-project/vllm/blob/432b1003f8ea7c871750f27bc82815a7ad0252d5/vllm/v1/worker/gpu/sample/logprob.py)、[sampler](https://github.com/vllm-project/vllm/blob/432b1003f8ea7c871750f27bc82815a7ad0252d5/vllm/v1/worker/gpu/sample/sampler.py)、[离线 Logprob 类型](https://github.com/vllm-project/vllm/blob/432b1003f8ea7c871750f27bc82815a7ad0252d5/vllm/logprobs.py)、[derender](https://github.com/vllm-project/vllm/blob/432b1003f8ea7c871750f27bc82815a7ad0252d5/vllm/renderers/online_derenderer.py)。

- `raw_logprobs`：原始 logits 的 log-softmax；`processed_logprobs`：采样处理后的归一化分数。`raw_logits/processed_logits` 是 logits，不是可直接放入概率比的 logprob。
- `logprobs=k` 是候选返回数量语义，包含实际 sampled token 的规则取决于 endpoint；不是 sampling mask。`logprobs=-1` 全量返回需核查引擎 max_logprobs 配额和 endpoint 支持，数据量可达 O(GV)。
- `logprob_token_ids` 请求指定输出候选；`prompt_logprob_token_ids` 对 prompt 位置进行指定 ID teacher scoring，不能与输出 token 列表混为一谈。
- 离线 `SampleLogprobs` 可为 `FlatLogprobs` 或位置字典序列，公共读取 `out.logprobs[j][out.token_ids[j]].logprob`。原生 token-mode HTTP 使用 `logprobs.content[j].token_id/logprob/top_logprobs`，OpenAI chat/completion 各有协议。

Trace Replay：开启 `enable_trace_replay`，请求 `trace_decode_token_ids` →保存请求轨迹 →正常 forward →按 GPU `total_len−prompt_len` 覆盖 sampled →计算该 forced token 的分数 →下一 decode。它不将 forced token 的概率改成1；有效长度按上下文及 max_tokens 限制。代码：[trace_replay.py](https://github.com/vllm-project/vllm/blob/432b1003f8ea7c871750f27bc82815a7ad0252d5/vllm/v1/worker/gpu/sample/trace_replay.py)。当前不兼容 speculative/structured outputs 等，不能与 M/R 所有组合直接拼接承诺。

上周 #55717/#59518/#60437/#59549 主要改变 L5；并未替换模型 L2 的计算。#61347 给训练端提供实际采样权重的 output-token spans，帮助区分异步更新与数值漂移。

## B：Batch 一致性

```text
B1 worker 初始化读取 VLLM_BATCH_INVARIANT
 → B2 init_batch_invariance：环境、BLAS/通信策略、平台注册与编译配置
 → B3 forward：Linear/GEMM、gate、attention、softmax、LoRA 和通信稳定路径
 → B4 相同输入与请求 seed 下验证单独/混批/换序的 token/logprob
```

代码：[初始化及 aten 覆盖](https://github.com/vllm-project/vllm/blob/432b1003f8ea7c871750f27bc82815a7ad0252d5/vllm/model_executor/determinism/batch_invariant.py)、[GateLinear](https://github.com/vllm-project/vllm/blob/432b1003f8ea7c871750f27bc82815a7ad0252d5/vllm/model_executor/layers/fused_moe/router/gate_linear.py)、[TP reduce](https://github.com/vllm-project/vllm/blob/432b1003f8ea7c871750f27bc82815a7ad0252d5/vllm/distributed/device_communicators/custom_all_reduce.py)、[官方范围](https://github.com/vllm-project/vllm/blob/432b1003f8ea7c871750f27bc82815a7ad0252d5/docs/features/batch_invariance.md)。

固定归约规则而非只固定随机数；TP 保留固定顺序 custom all-reduce 并限制其他可变路径。attention 后端按自身实现支持，FlashAttention 的一个例子是固定 num_splits=1。LoRA shrink 将 K 归约分成固定 chunk 再合并。平台分支不同，不统一宣称所有 aten 均被替换。

当前 beta；官方树内列 NVIDIA/ROCm/XPU，相应设备与后端限制见文档。Ascend 需独立核查 NPU runner、算子与 HCCL。TP 归约大小非16字节倍数、特定模型、量化与 speculative 的组合仍有边界。#52231 扩展 ROCm 的 B2/B3；#59985 修 gate 绕过；#60524 改 wNa16 为解包反量化后 BI matmul；#61118 修 B2 的 Inductor flag。量化分支修复不等于所有量化模型已验收。

验证：同 checkpoint/tokenizer/输入 token、dtype、TP/EP/backend，先 greedy 后固定 seed；对单独/混批/换序/不同 batch size 比较首个差异、max/mean Δlogprob、路由与支持集。生成分叉后应使用固定轨迹再对比相同上下文。记录吞吐与 TTFT/TPOT，容差由训练要求定义，不伪造测试通过结论。

## SWA bounded / decoder replay 的边界

DeepSeek-V4.1 prefix 命中后可能缺少滑窗 KV：命中 H、窗口 W 时回退 `min(H,W)`，`replay_start=H−min(H,W)`；窗口已经随远端 KV 加载则可跳过。scheduler →worker metadata →重建末尾窗口；decoder 后段可以 gather 所需行、切换 forward context 执行再 scatter，减少全前缀重算。

证据：[Scheduler._mark_prefix_replay](https://github.com/vllm-project/vllm/blob/432b1003f8ea7c871750f27bc82815a7ad0252d5/vllm/v1/core/sched/scheduler.py)、[DecoderReplayLayers](https://github.com/vllm-project/vllm/blob/432b1003f8ea7c871750f27bc82815a7ad0252d5/vllm/models/deepseek_v41/decoder_replay_layers.py)。它影响 RL rollout 缓存成本与正确性，不是向 trainer 导出 DSA/R3/hidden states 的 API。
