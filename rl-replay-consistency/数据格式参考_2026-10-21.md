## 数据格式契约与对齐示例（补充与修正）

基准：沿用 2026-10-21 固定主线 8e2beaa3bff595577a069d49d96bde9074294ec2。以下明确区分公共 API、内部 buffer，以及建议由训练数据集保存的元数据；示例均为人工构造，不是模型实测输出。

重要修正：R3 的 L 在当前代码中取 model_config.get_total_num_hidden_layers()，并非压紧后的 MoE 层数。layer_id 用于直接索引 layer 轴。只对实际绑定 capture 的层解释专家 ID；不能把未采集槽的初始 0 解释为专家 0。此前正文里简写 num_moe_layers 的说法，应以本节和 _get_routed_experts_shape 源码为准。GPU 捕获 int32 与返回 uint8/uint16 也必须分开。

### 表 6：公共字段的数据类型、shape 与空值

| 特性 / 字段 | Python 类型 / JSON 类型 | shape 与 dtype | 对齐与合法值 | 空值与边界 |
| --- | --- | --- | --- | --- |
| 通用 prompt_token_ids / token_ids | list[int] 或 Sequence[int]；JSON 整数数组 | prompt 为 [P]，completion 为 [G]；JSON 不携带 int32/int64 dtype | 同一 tokenizer/vocab 的 token ID；按整数比较，不按解码文本比较 | 以实际返回 token_ids 长度定义 G；不要用文本字符数或 stop 后文本推算 |
| R：routed_experts_prompt_start | int；JSON integer | 标量 O，默认 0 | 0≤O≤P；丢弃前 O 个 prompt 输入行，不是生成 token offset | 非法范围拒绝请求；需由调用方保存 O，不能从 npy 自动推回 |
| R：CompletionOutput.routed_experts | np.ndarray 或 None；HTTP string 或 null | [R,L,K]；R=P+G−1−O；L=总 hidden layers；K=experts_per_token；正常导出 uint8/uint16 | E≤256 用 uint8，否则 uint16；逻辑专家 ID 在 [0,E)；仅解释采集层槽 | 开关关闭或 forward 前已 abort 可为 None；容量/块缺失是错误，不能静默补零 |
| M：sampling_mask.token_ids | SamplingMask.token_ids 为 list[list[int]]；原生 HTTP sampling_mask 为二维 ragged 数组 | 外层 [G]；内层长度 S_i 可不同；元素为整数 token ID | 第 i 个集合对应 completion.token_ids[i]；正常有效采样的 token 应在该集合内 | 未请求为 None/null 或按序列化策略缺字段；不能把 null 当空支持集 [] |
| T：trace_decode_token_ids | list[int] 或 None；请求字段整数数组 | [T]；公共接口无固定机器 dtype | 非空；每个 token 为非负且小于 vocab_size；按 decode 输出顺序排列 | None 不启用；[] 拒绝；实际长度受上下文及有效 max_tokens 限制 |
| T/通用：CompletionOutput.logprobs | SampleLogprobs 或 None；不是固定 float 矩阵 | 可用位置序列访问，长度与输出 token 对齐；每位置 dict[int,Logprob]；内部也可为 FlatLogprobs | logprobs[i][token_ids[i]].logprob 取实际输出 token 的分数；rank 为 int 或 None | 未请求时 None；top-k 候选数量不是 vocab_size；不能当完整分布 |
| I：DSA 索引公共输出 | 尚无本次主线已确认的完整公共格式 | 不规定已生效 shape/dtype/编码 | PR 设计需要 token、层映射、坐标及有效长度 | 不将建议格式或 PR 字段写成主线 API |
| B：Batch Invariance 输出 | 沿用普通 token/logprob 输出 | 不新增 replay tensor 或独立 JSON 字段 | 记录开关、设备、权重和 batch 条件来解释对照结果 | 无独立 batch_replay 字段；比较指标属于评测数据 |

表 6 注释：P=模型实际接收的 prompt token 数（含模板/特殊 token），G=本条 completion 实际返回 token 数，O=prompt_start，R=路由输入行数，L=模型总 hidden-layer 轴，K=每 token 专家数，E=逻辑专家总数，T=输入轨迹长度。R 公式用于正常完成且有可用路由的生成请求；abort/无 forward 不能强套。NumPy dtype 由 npy header 提供；JSON integer 不等于承诺 int32。表中 null 与字段省略取决于具体 endpoint 序列化策略。

### 表 7：内部存储格式与导出转换

| 机制 / 内部字段 | dtype / shape | 有效数据规则 | 导出与消费者 |
| --- | --- | --- | --- |
| R：device_buffer | torch.int32，[max_num_batched_tokens,L,K] | 仅本步实际 token 行、实际 capture 层有效；不是请求完整历史 | snapshot_routing_data(num_tokens) 选实际行并转为窄 dtype |
| R：snapshot / CPU record | torch/np uint8 或 uint16，[n,L,K] | n 为快照实际行；后续还需按请求划分并去除 rejected 行 | AuxOutput 按 KV hash 保存 block/tail，再 materialize 请求结果 |
| R：HTTP routed_experts | ASCII base64 字符串，内容为完整 .npy bytes | .npy 带 shape、dtype、order header；不是裸 int 数组 bytes | base64 decode → np.load(BytesIO(...),allow_pickle=False) |
| M：SamplingMaskTensors.token_ids | torch.int32，[B×Q,W] | 仅 counts[r] 个 ID 有效；counts>W 时紧凑行不完整，必须读取 packed_mask | 不直接返回整个 padded buffer |
| M：packed_mask / counts | uint8 [B×Q,ceil(V/8)]；int32 [B×Q] | token j 对应 byte=j//8，bit=j%8；little bit order；V 以外 padding bits 不用 | counts≤W 用 IDs[:counts]，否则 unpackbits(bitorder='little',count=V) |
| M：SamplingMaskLists CSR | np.int32 flat token_ids；np.int64 offsets [A+1] | 第 i 个集合为 flat[offsets[i]:offsets[i+1]]；单位置切片可 offsets=None | to_nested_list →公共 list[list[int]] |
| M：cu_num_generated_tokens | list[int] 或 None，[B+1] | 多位置 batch 用累计输出数区分每请求的若干集合 | slice_request 定位请求，再导出支持集；不把一个 speculative step 当一个 token |
| T：trace_token_ids / trace_len | StagedWriteTensor int32 [max_reqs,max_model_len]；UvaBackedTensor int32 [max_reqs] | 前 trace_len[req] 个 token 有效；未启用请求 trace_len=0 | GPU 根据 total_len−prompt_len 定位当前 trace token |
| T：sampled | 该 trace kernel 接收 int64 sampled，[本步请求数] | 只覆盖有轨迹且步号合法的请求 | 后续分数计算使用覆盖后的 token，logits 不因该覆盖被改成 one-hot |

表 7 注释：B=当前内部 batch 请求数，Q=每请求预留输出 slot 数（普通采样通常 1），V=vocab_size，A=筛出实际有效 slot 后的位置数。W=min(所需紧凑宽度,V,2048)，当前 MAX_COMPACT_SUPPORT=2048；同分 tie/大 top-k 可能让 counts>W，不能断言支持集长度永远≤top_k。未使用槽可能只有 counts=0，其余内存不保证可读为有效数据。本表是内部实现，不是要求 trainer 直接依赖内部结构。

### 表 8：next-token 位移与路由行映射示例

假设 prompt=[p0,p1,p2]，output=[y0,y1]，P=3、G=2、O=1，因此 R=3。以下 token 名称是符号；真实 token 数据仍用整数。

| R3 导出行 | 输入序列绝对位置 t=O+r | 本行记录哪个输入 token 的专家 | 该位置 logits 预测什么 | 对应输出 / mask 行 |
| --- | --- | --- | --- | --- |
| 不导出 | 0 | p0，被 O=1 过滤 | p1 | 非 completion 位置 |
| r=0 | 1 | p1 | p2 | 非 completion 位置 |
| r=1 | 2 | p2 | y0 | output[0] / sampling_mask[0] / logprobs[0] |
| r=2 | 3 | y0 | y1 | output[1] / sampling_mask[1] / logprobs[1] |
| 无路由行 | 4 | y1 尚未作为下一轮输入 forward | 未计算下一 token 的预测 | y1 已被前一位置采样，不等于 y1 自己有专家记录 |

表 8 注释：R3 记录的是输入 token 的执行路由；mask/logprob 记录的是该步预测的输出 token。输出 y_j 的预测位置为 t=P+j−1；若 t≥O，其对应 R3 行为 r=P+j−1−O。训练是否只重放 response 的输入路由、是否包含 prompt，取决于 trainer 的 forward/label shift；不能直接把 R3 的后 G 行当作每个生成 token 自身的路由。prompt offset 不应应用到 mask/logprob 的 completion 索引。

### 公共接口示例与解码

R3 HTTP 解码（choices[i].routed_experts；示例变量 choice、P、G、O 来自同一条请求）：

```python
import base64, io
import numpy as np

encoded = choice.get('routed_experts')
experts = None if encoded is None else np.load(
    io.BytesIO(base64.b64decode(encoded)), allow_pickle=False)
if experts is not None:
    assert experts.ndim == 3
    assert experts.shape[0] == P + G - 1 - O  # 正常完成请求
    assert experts.dtype in (np.dtype('uint8'), np.dtype('uint16'))
    # layer_ids 必须来自模型/capture 映射；不要默认所有槽都是 MoE 层。
```

说明：序列化器使用 np.save(...,allow_pickle=False) 再 base64。不要用 np.frombuffer(base64_decoded,dtype=...) 解整个 HTTP 值，那会把 .npy header 当数据。逻辑专家 ID 也不能直接当作 EP rank 本地专家索引，需要训练侧映射。

Sampling Mask + token-mode 原生 generate 返回片段（人工示意，省略其他必需/公共字段；不是 OpenAI chat logprobs 格式）：

```json
{
  "choices": [{
    "index": 0,
    "token_ids": [10, 20],
    "sampling_mask": [[10, 11], [20, 21, 22]],
    "logprobs": {"content": [
      {"token_id": 10, "logprob": -0.5108, "rank": 1,
       "top_logprobs": [{"token_id": 10, "logprob": -0.5108, "rank": 1},
                        {"token_id": 11, "logprob": -0.9163, "rank": 2}]},
      {"token_id": 20, "logprob": -0.6931, "rank": 1,
       "top_logprobs": [{"token_id": 20, "logprob": -0.6931, "rank": 1}]}
    ]}
  }]
}
```

说明：外层两项分别对齐 10、20；支持集不是按概率降序的 top_logprobs 列表。API top_logprobs 仅返回请求数量的候选，不保证覆盖整个支持集。离线 logprobs[i] 使用整数 ID 为 key，原生 token-mode HTTP 使用 token_id 字段；OpenAI endpoint 用其自身协议。原生流式的 mask 对齐该 chunk 的 delta token_ids；按 choice.index 分组累计，不能把每个 chunk 的第 0 项当作整个序列的第 0 项。R3 在终止输出返回整份记录时应接收一次，不能按 delta mask 的方式反复拼接。

Mask 内部 CSR 示例：flat=[10,11,20,21,22]、offsets=[0,2,5]，可还原 [[10,11],[20,21,22]]。packed bitmask 示例：V=10、S={1,3,9} 时 bytes=[10,2]，因为第 0 字节 bit1/bit3 置位，第 1 字节 bit1 置位；这是按 token ID 的 little-bit 编码，不是 ASCII 字符串。

Trace Replay 请求示例：

```python
params = SamplingParams(
    trace_decode_token_ids=[10, 20],
    max_tokens=2,
    logprobs=1,
)
# 引擎预先 enable_trace_replay=True；比较原始分布用 raw_logprobs。
# 对正常完成且容量足够的请求：output.token_ids == [10, 20]
# 分数：output.logprobs[j][output.token_ids[j]].logprob
```

长度说明修正：源码 _normalize_trace_replay_params 先按上下文裁剪 trace，再取 min(len(trace),有效 max_tokens)。因此要完整回放，应显式给足 max_tokens；不要把任意请求参数下都输出完整 T 个 token 当作接口保证。Trace 的 logprob 仍按所选 raw/processed 模式解释，不能以“强制 token”推断其概率为 1。

### 表 9：训练样本建议保留的元数据（非 vLLM 新增协议）

| 建议字段 | 建议类型 / 格式 | 用途与约束 |
| --- | --- | --- |
| schema_version / feature_set | string / list[string] | 给自己的数据格式编号，例如 rl-artifacts-v1；不要冒充 vLLM 内置字段 |
| request_id / choice_index | string / int | 多请求、多 completion 的归属；不能只按网络到达顺序拼接 |
| prompt_token_ids / output_token_ids | list[int] / list[int] | 保留实际模型输入，含模板和特殊 token；保存 P、G 可由长度导出 |
| tokenizer_revision / vocab_size | string / int | 保证 token ID 含义一致；模型名称相同不代表 tokenizer revision 相同 |
| model_revision / weight_version_spans | string / 带 version,start,end 的列表 | 固定 checkpoint；若一次输出跨权重版本，记录分段，不硬贴单个版本标签 |
| routed_experts_prompt_start / layer_ids | int / list[int] | 明确 O 和有效采集层；layer_ids 为训练数据元数据，当前 npy 不内嵌此映射 |
| artifact shape / dtype / encoding | list[int] / string / string | 保存导出数组规格及 .npy+base64 标识；避免裸 bytes 无法自描述 |
| sampling_params / logprobs_mode | object / string | 保存 temperature、top_k/top_p/min_p、penalties、seed 以及分数定义 |
| runtime_config | object | 设备、dtype/量化、TP/EP、backend、batch invariant、引擎 commit；用于可比性判断 |
| completion_status | object | finished、finish_reason、stop_reason、abort/truncation 状态，区分完整与部分数据 |

表 9 注释：这是落盘/传给 trainer 的建议封装，不是 vLLM 公共 API 已定义 schema。weight_version_spans 若使用 vLLM weight_versions，start/end 是 output-token 索引的左闭右开区间 [start,end)；只有实际提供的版本信息才可填写，不应编造。hidden-state 与 DSA selection 的未合入公共格式不在此擅自规定。
